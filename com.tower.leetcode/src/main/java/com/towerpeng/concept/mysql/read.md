MYSQL索引底层结构：B+树
1、快速查找，B+树是平衡多路二叉树，树的高度相对较低，能够快速定位到目标数据，在大数据量的情况下，B+树的查找效率更高
2、有序性，B+树的特点是节点上的键值是有序排列的，这使得范围查询，排序和分组操作中效率更高，对于mysql的查询操作常常涉及到范围查找，B+树能有效支持。
3、支持高效的插入和删除操作，B+树的平衡特性使得插入和删除操作相对简单，不需要进行大量的数据迁移，B+树叶子节点之间使用双向链表控制，可以快速定位插入或删除的位置。
4、适应磁盘存储：mysql通常要将数据存储在硬盘上，而不是内存中，B+树的节点大小被控制在硬盘页面大小的范围内，使得每次读取数据量最大化，减少IO操作。
5、支持有序存储和范围查找，B+树能够支持有序存储和范围查找，使得mysql的索引性能更高。

MVCC是多版本并发控制，Multi-Version Concurrency Control ，是一种数据库的并发控制机制，目标是保证数据一致性和隔离性的同时，提供更好的并发性能。
MVCC的原理：
1、每行数据都有多个版本：每行数据都有多个版本，每当对数据进行更新操作，不会覆盖原来的操作，而是生成新的版本，每个版本都有一个时间戳，用于标识该版本的创建时间。
2、读操作只读取符合时间条件版本，在读取数据时，事务只能看到创建时间早于事务开始时间的版本。这样可以保证事务读取的数据是一致的，不影响其他事务。
3、写操作保存多个版本：当进行写操作时，会生成新版本并更新到数据航中，旧的版本仍然存在，不会被删除，这样可以保证数据一致性。
4、版本控制：为了维护数据的一致性和隔离性，mvcc使用了版本控制，在事务执行过程中，只能读取到版本号小于等于事务开始的版本，这样可以保证读取的数据在事务开始时是一致的
5、垃圾回收，为了防止旧版本无限增加，增加数据库的存储空间，mvcc采用了垃圾回收机制，当一个事务提交时，系统会检查该事务产生的版本是否有其他事务使用，如果没有，该版本会被删除，释放空间。

MVCC 的核心思想是：当多个事务同时操作同一数据时，每个事务看到的都是数据在特定时间点的快照（版本）。写操作会创建新版本，而读操作可以读取旧版本，从而避免加锁带来的等待。
InnoDB（MySQL 的常用存储引擎）是 MVCC 的典型实现。
在 MySQL 的 InnoDB 存储引擎中，读已提交（READ COMMITTED）和可重复读（REPEATABLE READ）这两个隔离级别主要依靠 MVCC 来实现一致性非锁定读（快照读）。
另外两个级别（读未提交、串行化）则基本不依赖 MVCC 或通过加锁实现。

事务的隔离级别：
1、读未提交Read-uncommitted，最低的隔离级别，事务可以读到未提交的数据，可能出现脏读，幻读，不可重复读
2、读已提交Read-committed，事务可以读到已提交的数据，但是同一事务中，多次读取同一行数据可能出现不一致的情况，可能会出现幻读，不可重复读
3、可重复读Read-Repeatable，在同一个事务内多次读取到同一行的数据始终保持一致。MYSQL的默认隔离级别就是可重复读，通过MVCC机制来实现，在读取操作期间不会看到其他事务的修改，有效的解决了不可重复读的问题
4、串行化Serialzable，串行化是最高级别，串行化执行可以避免脏读，幻读，不可重复读，但是并发性能较差，导致大量锁竞争和资源争抢。
