缓存三大场景（缓存穿透，缓存击穿，缓存雪崩）：
1、缓存穿透：指用户请求的数据缓存和数据库都不存在，从而每次请求都直接打到数据库中。
解决方案：
布隆过滤器：用布隆过滤器在访问缓存前进行一次快速判断，过滤掉不可能存在的数据。（不存在的一定不存在，存在的可能不存在，假阳性）
缓存空对象：对于频繁访问的热点数据进行空缓存。
2、缓存击穿：缓存中某个热点数据突然失效，并在大量请求同时涌入数据库，导致数据库压力暴增，甚至崩溃的情况。
解决方案：
设置热点数据永不过期：对于经常访问的热点数据，设置一个很长的过期时间或者不过期。
访问数据库加锁：在缓存失效后，通过锁来控制数据库访问，确保只有一个请求能去查询数据库并更新缓存。
3、缓存血崩：某时刻缓存大量失效，导致瞬时大量请求涌入数据库，或者由于节点故障导致缓存失效。
解决方案：
缓存过期时间增加随机数：避免大量缓存同一时间过期
多级缓存：配置多级缓存，如本地缓存+redis缓存。

redisZset为什么选择跳表，而不用b+树，
redis选择跳表，并不是因为算法理论比B+树强，而是因为在内存场景下做到了收益和成本的平衡
1、性能不输，同样是o（logn）效率
2、实现更轻，代码少，bug率直线下降
3、并发更强，没有复杂的树平衡锁竞争
内存数据库，所有操作都是在内存中执行，没有磁盘io的开销，支持高效的区间查询和操作。

Redis 对过期 key 的处理采用两种策略结合的方式：
惰性删除 + 定期删除，这是一种在性能和内存之间取得平衡的经典设计。
惰性删除：当客户端尝试访问一个 key 时，Redis 会先检查它是否已过期。如果过期，Redis 会立即将其删除，然后返回 nil。
定期删除：Redis 会每隔一段时间（默认 100ms）随机抽取一部分设置了过期时间的 key，检查并删除其中的过期 key。
内存淘汰机制（兜底策略）：当内存耗尽（达到 maxmemory 限制）时，Redis 的内存淘汰策略会介入，即使 key 没过期也可能被删除。常见策略包括：
LRU（最近最少使用）：淘汰最近最少使用的 key。
LFU（最不经常使用）：淘汰访问频率最低的 key。
TTL（即将过期）：淘汰即将过期的 key。
随机淘汰：随机删除 key。

redis持久化机制
1、RDB持久化，RDB是快照持久化方式，它会将redis在某个时间点的数据以二进制方式保存在文件中，RDB优点是生成文件比AOF小，恢复速度更快，适用于备份和灾难恢复。
2、AOF持久化，AOF是追加日志持久化方式，它会将redis执行的写命令追加到文件的末尾，当redis重启时，它会重新执行写命令来恢复数据。AOF提供了更可靠的持久化方式，因为他可以保证每个写操作都被记录，并且不发生数据丢失。
3、混合持久化，混合持久化是介于RDB和AOF之间的一种持久化方式，它会将RDB持久化文件保存在磁盘上，AOF持久化文件保存在内存中，当AOF文件达到一定大小时，会进行RDB持久化，并删除AOF文件。
实际生产更适合用混合持久化。
